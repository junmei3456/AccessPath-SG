# AccessPath-SG: SVI, SOM and Initial Screening
AR5958A Final Project. This folder contains the core acquisition, image-grouping and initial feature-screening workflow, its required review records and final CSV/GeoJSON outputs.

## Core workflow
| Stage | Code | Purpose |
| --- | --- | --- |
| SVI acquisition | `01_svi_acquisition/TB_Havelock_SVI_download.ipynb` | Download eligible left/right Google Street View images using the manifest and route filter. |
| Additional sampling | `01_svi_acquisition/block20_svi.py` | Acquire Block20 views, reusing existing panorama views where possible. |
| SOM | `02_som/Week02_SearchEngine_Background_codes.nb`, `TB_Havelock_SOM_cells.wl` | Load course utilities; extract Wide ResNet features; group images and export assignments. |
| Visibility | `03_initial_screening/score_all.py` | Mask2Former visibility fractions and exploratory CLIP scores. |
| Candidate detection | `dino_all.py`, `dino_labels.py` | Grounding DINO detection with multiple phrases and individual feature prompts. |
| Detection tables | `prepare_detection_tables.py` | Convert the two detector JSONL outputs into the CSV tables used by the review pool. |
| Review and export | `pool.py`, `export_labels.py` | Build the candidate pool, review representative views, propagate labels to repeated views and export point features. |

The screening scripts in the table are inside `03_initial_screening/`. Review sheets generated by `pool.py` are part of the labelling workflow. Standalone plotting/checking utilities, pilot scripts, sample runs, checkpoints, duplicate notebooks and unrelated context layers have been removed.

## Results
| Batch | Acquired images | Labelled image views | Labelled sampling points |
| --- | ---: | ---: | ---: |
| TB-Havelock | 4,238 | 420 | 350 |
| Block20 | 1,656 | 326 | 289 |

Acquisition GeoJSONs are in `01_svi_acquisition/svi_output*`. Final visibility CSVs, feature CSVs and feature GeoJSONs are in `03_initial_screening/outputs/output_TB` and `output_block20`. Saved full-run SOM assignments are in `02_som/outputs/run_cells.csv`; the screening folder also retains the same file because its scripts read it there.

The six exported categories are stairs, ramp, overhead_bridge, covered_walkway, underpass and construction_obstruction. These results combine model-assisted candidate selection, visual-review records and repeated-view propagation. They are not ground-truth accessibility measurements or direct Qwen VLM predictions. A missing label does not establish that a feature is absent.

## Running the code
1. Install `requirements.txt`; install `requirements_initial_screening.txt` for GPU/model inference. Mathematica/Wolfram Language is required separately for SOM. Versions are inferred from imports, not locked.
2. Configure Google credentials (`GOOGLE_SV_KEY`) and source-image paths. Acquisition uses test/request limits; `block20_svi.py --download` enables image downloads.
3. Evaluate the SOM background notebook before the project-specific `.wl` cells. The `.wl` file configures a new 10 x 10 run; saved assignments have cell IDs 1-225. Candidate rules in `pool.py` use those earlier cell IDs and require revision after retraining.
4. Screening scripts take the screening working folder as their first argument. Run `score_all.py`, both DINO scripts, `prepare_detection_tables.py`, `pool.py`, visual review, then `export_labels.py`. Reuse saved review records to inspect the existing export without rerunning the models. The detector JSONL files are generated during inference and are not retained in this compact collection.

Most original scripts retain absolute paths to the original Final Project DATA/SOM folders. Update BASE, POINTS, KEY_FILE, IMG, OUT, GJ, imagefolder and workingfolder as applicable before rerunning; setting the working-folder argument alone does not redirect every output. Raw JPG collections, credentials and model weights are not included. Model scripts use CUDA and offline cached weights for Mask2Former Mapillary Vistas, CLIP ViT-L/14 and Grounding DINO base.

## Reproduction limits
- All 420 TB feature-label sets were verified against the saved review records and representative-view mapping.
- Saved visibility labels differ from the rule currently in `score_all.py` for 395 TB and 130 Block20 rows. Their final rule revision was not recovered; archived outputs are preserved unchanged.
- The additional Block20 label-export/inheritance generator and saved CLIP score CSV were not recovered. Block20 feature results remain available for inspection.
- The course background notebook supplies baseline functions; its inclusion does not imply project-specific authorship of all baseline code.

This compact archive accompanies the Qwen VLM experiments in the repository's [`vlm/`](../vlm/) folder. Raw imagery and model weights are supplied separately.
